# 0.6.0 preparation: reliability and security review

Date: 2026-11-14. Scope: `main` at `34f68b5` (0.5.0 plus winget manifests), the release binaries, the desktop app, the MCP server and the review Action. Method: code reading, local tests on Windows, hostile inputs, and controlled pull requests in a private sandbox repository. This is not a professional penetration test.

Status labels: **Verified**, **Failed**, **Not tested**, **Blocked by user action**, **Recommended**.

## 1. Summary

| # | Area | Finding | Severity | Status |
| --- | --- | --- | --- | --- |
| S1 | Review Action | It edits *any* PR comment that starts with `<!-- tracemark-review -->`. A participant can post such a comment, and the next run rewrites it with the review. The review then shows under that person's name, and they can edit it into a fake "No rule flagged a risk". | Medium | **Failed, then fixed** on branch `fix-0.6.0-validation`: the action now updates only comments written by its own account. Tested in the sandbox. |
| S2 | Review rules | A whitespace edit to a caller's file hides `signature-callers-untouched`. A real signature break went from HIGH to "No rule flagged a risk". | Medium | **Failed**, not fixed. Decision needed. |
| S3 | Review rules | Imports are not checked. A file rename that breaks every importer gets "No rule flagged a risk". | Medium: false all-clear | **Failed**. Now documented in the printed limitations; fix proposed. |
| S4 | Call linking | Rust `Type::f()` is linked on `f` alone. About 84 of 127 such links in this repository are wrong, and they inflate review impact. | Medium: wrong `Inferred` facts | **Failed**. Documented; fix proposed. |
| S5 | Index | A damaged index file blocked every command. | Low | **Failed, then fixed** on the branch. Regression test added. |
| S6 | Action integrity | The action checks the SHA-256 of the binary it downloads, but the checksum comes from the same release. That proves integrity in transit, not who built it. | Low | **Recommended**: also run `gh attestation verify` in the action. |
| S7 | CI | `actions/checkout` pinned at v4 runs on deprecated Node 20. GitHub forces it to Node 24 and warns on every run. | Low: maintenance | **Recommended**: bump the pinned SHA. |
| S8 | Agent data flow | MCP tool results, including signatures and paths, go to whatever model the agent uses. Tracemark itself sends nothing. | Info | **Recommended**: say so in the README MCP section. |

No critical or high-severity issue that would leak code or run attacker input was found.

## 2. Parser and index correctness

| Check | Result | Evidence |
| --- | --- | --- |
| Test suite | **Verified** | `cargo +stable-x86_64-pc-windows-gnu test --workspace --locked`: 57 passed, 0 failed (56 on `main`, plus the new test). `cargo clippy … -D warnings` clean. `cargo fmt --all --check` clean. Windows only; CI covers Linux and macOS. |
| Scan in one transaction | **Verified** (code) | `Index::scan` uses one SQLite transaction. An interrupted scan keeps the old index. |
| Incremental rescan | **Verified** | `coop-ai-connect`: `0 reparsed, 1534 unchanged` on a no-op rescan. After edits, only the changed files were reparsed. |
| Deleted and renamed files | **Verified** | The deletion was reported, with call sites that still use the removed names. The rename was reported as a rename. Existing tests `rescans_only_changed_files_and_relinks_the_rest` and `secret_removed_by_a_rescan_is_not_left_in_the_file` pass. |
| Damaged index | **Failed → fixed** | Before: `error: index database: file is not a database` from every command (CLI, MCP, desktop). After: the file is replaced and rebuilt. Only SQLite's `NotADatabase` and `DatabaseCorrupt` errors trigger this. A locked database is still reported as an error, so a second process is never disrupted. Test: `corrupt_index_file_is_rebuilt`. |
| Concurrent access | **Verified** (light) | A query and a second scan ran while a full scan was in progress. No errors. Not stress-tested. |
| Relationship resolution | **Failed** for Rust paths (S4) and JSX (blind spot) | See sections 6 and 8 of the validation report. |
| Known limits still visible | **Verified** | "Calls linked by name", "Rust macro calls missed", "Rust and Python imports not resolved", and "renames appear as removed plus added" are in the README, the guide and the printed limitations. The new limits for JSX, Rust `Type::f()` and unchecked imports were added in the same change. |

## 3. Injection and untrusted input

| Check | Result | Evidence |
| --- | --- | --- |
| HTML report | **Verified** (code and existing test) | Every project string goes through `esc` (`& < > " '`). The report has no scripts and no external resources. Existing hostile-input test passes. |
| PR comment markdown | **Verified** (code) | Every project name and path is put in a code span. Backticks become `'`, newlines become spaces, and `|` is escaped in finding text. A path containing `|` inside a table code span can still break the table layout (cosmetic). |
| Desktop UI | **Verified** (code) | All project text is set with `textContent`. CSP is `default-src 'self'; script-src 'self'`. The capability allows only `core:default` and `dialog:allow-open`. |
| SQL | **Verified** (code) | All values are bound parameters. |
| git invocation | **Verified** | Arguments are passed without a shell. A `--base` starting with `-` is rejected (`invalid --base`). `core.fsmonitor=false`, `GIT_OPTIONAL_LOCKS=0`, `GIT_TERMINAL_PROMPT=0`. |
| MCP input validation | **Verified** (raw JSON-RPC) | Malformed JSON → -32700. Batches → -32600. Unknown method → -32601. Unknown tool or missing argument → -32602. `depth` is clamped to 1–10 (`999999` tested). No tool accepts a path. The project root is fixed at start-up, so a tool cannot reach another folder. |
| Path traversal | **Verified** | Discovery uses `follow_links(false)`. A symbol query for `../../etc` returns an empty list. It is a name filter, not a path. |
| `unsafe` Rust | **Verified** | None in `crates/*/src` or `desktop/src`. |

## 4. Secrets, logs and network

| Check | Result | Evidence |
| --- | --- | --- |
| Secrets in signatures | **Verified** | A hostile sample: TS template literals, `??` defaults, nested object literals, and Python bytes and f-strings. All of them were shown as `"<redacted>"`. `strings index.db` found none of the planted values. `secure_delete` is on. |
| Index committed by accident | **Verified** | `.tracemark/.gitignore` contains `*`. |
| Logs | **Verified** (code) | No log files. Errors go to stderr only. The MCP server writes only JSON-RPC to stdout. |
| Network, core and CLI | **Verified** | `Cargo.lock` for the workspace has no HTTP or socket crate. No `TcpStream` or `UdpSocket` in the source. |
| Network, desktop | **Partly verified** | The app's own code makes no network calls, and CSP `connect-src` allows only IPC. `desktop/Cargo.lock` does contain `reqwest` and `hyper` through `tauri`. They do not appear in the Windows normal dependency tree (`cargo tree -i reqwest -e normal`). **Recommended**: confirm with a Tauri feature audit that no HTTP client is compiled into any desktop target. |
| Filesystem writes | **Verified** (code) | Writes only under `<project>/.tracemark/`. The new recovery code deletes only `<project>/.tracemark/index.db`, and only when SQLite reports it corrupt. |

## 5. GitHub Action and CI permissions

| Check | Result | Evidence |
| --- | --- | --- |
| Workflow permissions | **Verified** | Every workflow defaults to `contents: read`. `review.yml` adds `pull-requests: write`. Only the release `publish` job has `contents: write`, `id-token: write` and `attestations: write`. No `pull_request_target`. |
| Pinned actions | **Verified** | Every third-party action is pinned to a commit SHA. |
| Release provenance | **Verified** | `gh attestation verify` on the Windows installer and the CLI zip: signer `release.yml@refs/tags/v0.5.0`, source `493ac85`. |
| Action inputs | **Verified** (code) | `version` is checked against `[0-9A-Za-z.-]`. Inputs reach scripts through `env:`, not inline `${{ }}` expansion. |
| Can it approve unsafe changes? | **Verified: it never approves** | It posts a comment and sets a check status. With `fail-on: never` (the default) the check is green whatever it finds. S2 and S3 show realistic unsafe changes that pass even `fail-on: blocker`. |
| Duplicate comments | **Verified** | One comment per PR, updated on each push. |
| Comment spoofing (S1) | **Failed → fixed** | See the summary. Fix in `action.yml`: the action finds its own login (`gh api user`, or `github-actions[bot]` for the default token) and selects comments by that author plus the marker. |
| Dependency advisories | **Verified (CI)** | `cargo-deny` is green on `main` ([run](https://github.com/Gabions256/tracemark/actions/runs/43571487845)) and in the desktop workflow. The desktop ignores one advisory, `RUSTSEC-2024-0370` (`proc-macro-error`, unmaintained, build-time only through Tauri's Linux GTK 3 bindings), with a written reason. `cargo deny` is not installed locally, so it was not re-run here. |

## 6. Not tested

- macOS and Linux desktop builds, and code signing (no certificates).
- Running the desktop with the fixes. The desktop cannot be built locally because the MSVC toolchain is missing.
- Fuzzing the parsers with random input. Tree-sitter error recovery is covered only by the existing malformed-input tests.
- Very large repositories (over 10 000 files) and memory use.
- MCP behaviour when the server is killed in the middle of a Claude Code session.
